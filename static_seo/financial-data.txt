# financial-data.txt for https://toscale.pro
#
# Machine-readable provenance and licensing disclosure for the financial data
# this site publishes. Serve at https://toscale.pro/financial-data.txt as
# text/plain, UTF-8, no BOM.
#
# There is no ratified standard for this file. The Overgrow knowledge base
# defines llms.txt, sitemap.xml and robots.txt and defines nothing here, so
# the format below borrows the shape of RFC 9116 (security.txt): one
# `Field: value` per line, `#` comments on their own line, repeated fields
# permitted where a list is meant. That convention is chosen because it is the
# one already understood for well-known text files at a site root — a parser
# written for security.txt reads this without modification.
#
# Every value below is either a published product fact or an explicit TODO.
# Nothing here is estimated. A financial data vendor that guesses at its own
# provenance disclosure has undermined the only thing it sells.

# -- Update cadence ---------------------------------------------------------
#
# Cadence is stated as the configured floor between sweeps, not as a promise
# of latency. The scheduler asks the database whether the newest fact is older
# than the newest thing SEC has published and sweeps only when the answer is
# yes; these figures are the minimum interval between two such checks, which
# is the honest number. Defaults from src/config/settings.py; each is
# overridable by the environment variable named beside it.

# -- Accuracy methodology ---------------------------------------------------
#
# The claim and the test that backs it, in the same block, because an accuracy
# figure without its method is a marketing number.

Accuracy-Reported: 0.999
Accuracy-Industry-Baseline: 0.786
Accuracy-Metric: correct XBRL tag selection per balance-sheet line item
Accuracy-Attribution: both figures are published by To Scale and are not third-party audited
Method: accounting-identity-reconciliation
Method-Identity: Assets = Liabilities + Equity
Method-Description: A single filing may tag one concept many times — once per reportable segment and per consolidated subsidiary. JPMorgan's filings carry 23 distinct tags for Total Assets. Candidate tags are tested against the accounting identity and the set that reconciles is the set that is served, so the selection is deterministic and independently checkable rather than heuristic.
Method-Model-In-Path: none
Derived-Values-Flagged: yes — a page marks a figure computed from the identity rather than stated by the filer
Missing-Values-Flagged: yes — components a filer did not report separately are named on the page rather than zero-filled
