# Changelog

## Unreleased: release/period-fix

### Filing dates on historical balance sheets change

`filing_date` on a balance sheet and on each of its line items now means **the filing that first reported that value**. The sheet's own `filing_date` is **the filing that supplied total assets**.

Why: the old rule dated a figure by the *latest* filing that reported it. That is the right choice for the value (a restatement must beat the original) but the wrong one for the date. A later filing that only repeats a figure moves the printed date forward: every 10-Q repeats the prior year end as a comparative, and every statement of equity repeats its opening balance. Apple's 2026-03-31 quarter showed equity "filed 2026-07-31" beside assets "filed 2026-05-01", and a year on it would have said a year later.

What you will see:

- Newest sheets: almost unchanged (about 0.5% of companies' newest sheet changes date).
- Historical sheets (`/api/company/{ticker}/history`, `?as_of=`, the company page for an older period, `/api/verify` provenance links): about 61% of sheets since 2025 print a different header date, a median of about six months earlier. Values do not change.
- `/api/verify` builds its SEC filing link from the sheet's `filing_date`; for historical sheets it now points to the filing that carried the balance sheet, not a later filing that repeated a figure.
- A real restatement still takes the date of the filing that introduced the new value.

### The dataset CSV: one row per real quarter, one new column, and what the pages say

- **Month-end copies are gone from the file.** A quarter loaded by both SEC routes used to be written twice (Apple's 2026-03-28 and 2026-03-31, total assets in both). The file now applies the same rule as the API: a month-end row whose real-dated twin (same filing, source and metric) has the same value is dropped; one with no twin is re-dated to the real period end, not dropped. On the live table that removed 7,560 rows and re-dated 2,534; the file is 1,257,194 rows, down from 1,264,751.
- **New last column, `period_note`.** Blank on every row except the two copies of a figure whose value differs between the month-end date and the real date (none today); each says "value differs from the <other date> row". A fiscal-year figure and its fourth quarter end on the same day and are not twins: for an income-statement or cash-flow metric they are never paired, both are written under their own dates, and the fiscal-year row's note says "fiscal-year value; the fourth-quarter value is the <date> row" (3 rows today, all UFI). It is the last column, so a reader that takes the first nine by position sees the file it saw before.
- **Filings loaded only from SEC's bulk data sets keep SEC's month-end date**, up to 15 days from the actual period end. The pricing page, the dataset page and the response headers now say so.
- **The pages describe how the download works.** Each download is built from the database when it is requested, so downloading again later includes any filings loaded since; a copy you save does not change. The old copy ("static snapshot", "never updates", "buy again") was wrong. The header `X-Dataset-Static` is replaced by `X-Dataset-Freshness` and `X-Dataset-Period-Ends`.
- **Wording about revisions is corrected everywhere it was wrong.** Pages and machine-readable files said figures were "not restated" or "never restated", that "the earliest filing wins", or that a later filing does not revise a figure (`static_seo/financial-data.txt`). The code does the opposite: the default view shows the revised value under the later filing's date, and `as_of` returns the value known on the date asked. The compare-table rows that claimed "As-reported, not restated: Yes" now say what is true (filing date on every figure; point-in-time `as_of` history). `src/mcp_server.py` still carries the old wording and is being handled separately.
- **Revenue tag for filers that include assessed tax.** `RevenueFromContractWithCustomerIncludingAssessedTax` was missing from the revenue tag list, so a filer that reports only that line (Hooker Furnishings) had its revenue dropped from bulk loads and read from a different tag on the frames route (a -$522,000 `Revenues` adjustment instead of $63,250,000). It now ranks after the Excluding variant and before `Revenues`. Data already stored is not rewritten: affected filers pick it up on their next load.
- **When both SEC routes loaded a filing, the figure the company published wins.** The bulk data sets carry only the tags a filer presents on its statements (with month-end-rounded dates); the frames route sees every fact, notes included, and takes the best-ranked tag (often a note-level subset). For one filing that left two copies a few days apart and the site showed the note-level one. The month-end-dated copy of such a pair now wins, in the CSV, the balance sheet and the income statement. Changes today: KO marketable securities 2,625M to 2,842M; DE 1,303M to 1,350M; TPR long-term debt 2,396.6M to 2,379.0M; LDOS revenue 4,548M to 4,558M; SNA 1,225.8M to 1,334.8M; Hooker cost of goods 4.3M to 43.2M. Six rows leave the CSV (1,257,188). Only a different tag settles it: one tag reported twice at two values is still flagged.
- **EPS from the bulk route.** SEC's bulk files label per-share facts `USD` (2026q3: 24,767 rows, none `USD/shares`), but the loader required `USD/shares`, so it dropped every EPS fact and all stored `eps_diluted` rows came from the frames route (newest quarter only, no annual figure, no history). The loader now accepts `USD` as well as `USD/shares`; foreign-currency EPS is still refused. A parse-only run on 2026q3 yields 9,093 EPS rows for 4,306 tickers, including each fiscal year (CRS 10.52, GIS -0.16). Nothing is backfilled by this change; stored rows are not rewritten.
- **Coverage claims narrowed.** "Every period is checked" is now "each period is checked when the filing reports the lines the check needs; where it does not, the check returns `not_testable` instead of passing" (compare tables, pricing, home, API docs, dashboard, landing, blog, structured data, `llms.txt`). About 11% of tickers with gross profit or cost of goods have no usable revenue row today. Diluted EPS is available for the most recent quarter only until history is loaded: stated in `llms.txt`, on the dataset page, in a new `X-Dataset-Eps-Coverage` response header, and in the restatements-page label. `src/mcp_server.py` still carries the old wording and is handled separately.
- **Row counts are the file's.** The pages quoted the table's size (about 2.0M); the file is about 1.3M. `facts_label()` feeds the same number to the home page, `/api`, the blog and `llms.txt`, so those drop too.

### Other changes in this release

- **Period ends.** SEC's bulk datasets round a period end to the nearest month end (Apple's 2026-06-27 reads 06-30). The real date is kept and every read path treats a rounded copy and its real-dated twin as one period. Read-side only: no data was rewritten.
- **Page freshness** is judged on the canonical newest period.
- **MCP.** The numbers are in the text answer; equity is labelled for what it is ("Equity incl. noncontrolling interest" when it includes the noncontrolling interest); `filer_totals_agree` is `null` when the filing balances; unknown tickers are `isError: true`; plan limits on `years` are stated; chart-rendering fields are gone from `check_balance_sheet`.
- **Site.** The equity band reads "Equity incl. NCI" and the legend "Equity incl. noncontrolling interest" where the filer's combined equity total is shown. The sign-in panel prices are labelled as Canadian dollars.
